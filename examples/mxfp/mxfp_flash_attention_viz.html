MXFP8 Flash Attention Kernel

File: mxfp8_flash_attention.py | Config: BLOCK_M=128, BLOCK_N=64, num_warps=4, num_stages=3

▶ Outer: load Q [128, 128] fp8 + Q_scale [128, 4] once per M-tile
▶ Inner loop: for start_n in range(0, N_CTX, 64)
1 Load K [64, 128] fp8_e4m3 + K_scale [64, 4] uint8 cp.async / tl.load
2 Q @ K^T → QK [128, 64] via tl.dot_scaled(q, q_scale, "e4m3", k.T, k_scale, "e4m3") tcgen05.mma...kind::mxf8f6f4.block_scale
3 Online Softmax: m_ij = max(m_i, rowmax(QK*scale)); P = exp2(QK*scale - m_ij); acc *= exp2(m_i - m_ij) MUFU.EX2, FMNMX, FMUL
4 Cast P → fp8: p.to(tl.float8e4nv) + P_scale = 0x7F (hardcoded 1.0) F2FP.RTN.FP8
5 Load V [128, 64] fp8_e4m3 (transposed: [D, BLOCK_N]) + V_scale [128, 2] uint8 cp.async / tl.load
6 P @ V → acc [128, 128] via tl.dot_scaled(p_fp8, p_scale, "e4m3", v, v_scale, "e4m3", acc) tcgen05.mma...kind::mxf8f6f4.block_scale
7 Normalize: output = acc / l_i; Store [128, 128] fp32 tl.store

Key Design Choices

V Layout: Transposed [D, N]

V stored as [HEAD_DIM, N_CTX] so reduction dim (N) is contiguous for dot_scaled's RHS scale indexing: V_scale [D, N/32]

P Scale: Hardcoded 0x7F = 1.0

After softmax, max(P)=1.0. E8M0 encoding: 2^(127-127)=1.0. No dynamic scale needed — saves ALU.

Scale Along Reduce Dim

Q/K scales along HEAD_DIM (K-dim of Q@K^T). V scale along N (K-dim of P@V). rhs_scale shape: [N, K//32].

Compiler Workaround

Disabled OptimizeAccumulatorInit pass in nvidia/compiler.py to fix "uninitialized alloc must have mutable memdesc" error with non-accumulating dot_scaled.

MXFP4 Flash Attention Kernel

File: mxfp4_flash_attention.py | Config: BLOCK_M=128, BLOCK_N=64, num_warps=4, num_stages=4

▶ Outer: load Q [128, 64] packed uint8 (128 e2m1 elements packed into 64 bytes) + Q_scale [128, 4]
▶ Inner loop: for start_n in range(0, N_CTX, 64)
1 Load K [64, 64] packed uint8 (64×128 e2m1 elements) + K_scale [64, 4] uint8 cp.async / tl.load
2 Q @ K^T → QK [128, 64] via tl.dot_scaled(q, q_scale, "e2m1", k.T, k_scale, "e2m1") tcgen05.mma...kind::mxf8f6f4.block_scale (fp4 operands)
3 Online Softmax: m_ij, P = exp2(...), acc rescale (same as MXFP8) MUFU.EX2, FMNMX, FMUL
4a P Dynamic Scale: per-group-of-32 amax → E8M0 scale + inv_scale FMNMX, MUFU.LOG2, ceil, MUFU.EX2
4b P → FP4: scale P, reshape to even/odd pairs, cvt.rn.satfinite.e2m1x2.f32 cvt.rn.satfinite.e2m1x2.f32 (PTX inline asm)
5 Load V [128, 32] packed uint8 (128×64 e2m1 transposed) + V_scale [128, 2] uint8 cp.async / tl.load
6 P @ V → acc [128, 128] via tl.dot_scaled(p_packed, p_scale, "e2m1", v, v_scale, "e2m1", acc) tcgen05.mma...kind::mxf8f6f4.block_scale (fp4 operands)
7 Normalize: output = acc / l_i; Store [128, 128] fp32 tl.store

FP4 Packing: PTX cvt.rn.satfinite.e2m1x2.f32

// Pack two float32 → one uint8 with two E2M1 nibbles
@triton.jit
def _fp32x2_to_fp4x2(x_lo, x_hi):
    // Low nibble = x_lo, High nibble = x_hi
    asm """
      .reg .b8 tmp;
      cvt.rn.satfinite.e2m1x2.f32 tmp, $hi, $lo;
      cvt.u32.u8 $out, tmp;
    """

// Packing layout in each byte:
// Bit 7..4: element[2i+1] (odd index)
// Bit 3..0: element[2i] (even index)

// E2M1 nibble encoding (4 bits): S|EE|M
// 0b0000=0.0 0b0001=0.5 0b0010=1.0 0b0011=1.5
// 0b0100=2.0 0b0101=3.0 0b0110=4.0 0b0111=6.0
// + 0b1000 for negative sign

Conclusion

MXFP8: Production Ready

FP8 E4M3 with E8M0 block scales preserves model quality perfectly — zero degradation even on a 0.6B model. Suitable as a drop-in replacement for FP16 attention in inference.

MXFP4: Needs QAT

FP4 E2M1 with only 8 representable magnitudes causes significant quality loss when applied post-training. Requires quantization-aware training or careful calibration to be practical.
