Flash Attention Stages in Triton

Based on 06-fused-attention.py — Two distinct meanings of "stage"

1. Causal Masking Stages (STAGE parameter)

The STAGE parameter controls how the attention matrix is partitioned for causal masking:

• STAGE=3 (causal=True): Split into Stage 1 (off-diagonal, no mask needed) + Stage 2 (on-diagonal, apply mask)

• STAGE=1 (causal=False): Process everything in one pass (Stage 3 internally = full range, no mask)

Causal Mode (STAGE=3)

Q rows (BLOCK_M) × K columns (BLOCK_N)

Non-Causal Mode (STAGE=1)

Full attention — no masking

Stage 1: Off-band (no mask)
Stage 2: On-band (causal mask)
Masked out (-inf)

# In _attn_fwd_inner: if STAGE == 1: # Off-band: fully valid region lo, hi = 0, start_m * BLOCK_M elif STAGE == 2: # On-band: diagonal block with causal mask lo, hi = start_m * BLOCK_M, (start_m + 1) * BLOCK_M else: # STAGE == 3: non-causal, full range lo, hi = 0, N_CTX

How the kernel dispatches stages:

# In _attn_fwd (the main kernel): if STAGE & 1: # True for STAGE=1 (non-causal) and STAGE=3 (causal) # Calls _attn_fwd_inner with STAGE = 4-STAGE # STAGE=3 → inner gets 1 (off-band) # STAGE=1 → inner gets 3 (full range, no mask) if STAGE & 2: # True only for STAGE=3 (causal) # Calls _attn_fwd_inner with STAGE=2 (on-band, masked)

2. Software Pipelining Stages (num_stages)

num_stages controls how many K/V blocks are prefetched ahead of computation, hiding memory latency via async copies.

The Triton compiler inserts cp.async (Ampere) or TMA loads (Hopper) to overlap loads with computation.

Trade-offs

More stages (3-4)

+ Better hides memory latency

+ Higher throughput for memory-bound kernels

- More shared memory for buffering

- Fewer concurrent blocks per SM

- Longer pipeline startup/drain

Fewer stages (1-2)

+ Less shared memory pressure

+ More blocks can run concurrently

+ Simpler; less register pressure

- May stall waiting for memory

- Lower utilization of memory bandwidth

3. Putting It Together

In the Triton flash attention kernel, both stage concepts work together:

Causal STAGE (algorithmic)

Splits Q×K attention into off-band + on-band to avoid unnecessary mask computation on blocks that are fully valid.

stage = 3 if causal else 1

num_stages (hardware)

Within each inner loop (off-band OR on-band), the compiler pipelines K/V block loads ahead of computation.

num_stages ∈ [2, 3, 4] on Hopper

# From the autotuning configs (line 136): configs = [ triton.Config({'BLOCK_M': BM, 'BLOCK_N': BN}, num_stages=s, num_warps=w) for BM in [64, 128] for BN in [32, 64, 128] for s in [2, 3, 4] # software pipelining stages for w in [4, 8] ] # The inner loop where pipelining applies (line 69): for start_n in tl.range(lo, hi, BLOCK_N, warp_specialize=warp_specialize): k = desc_k.load(...) # async prefetch by compiler qk = tl.dot(q, k) # compute overlaps with next load v = desc_v.load(...) acc = tl.dot(p, v, acc)
